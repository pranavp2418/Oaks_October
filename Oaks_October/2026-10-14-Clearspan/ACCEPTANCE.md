# Clearspan: product and engineering contract

An inspection coordinator needs to cover high-priority asset checkpoints while respecting exclusion zones, a finite movement/inspection budget and a guaranteed return to base. This is an original software mission simulation, not robot control, real computer vision or a safety-certified planner. Input is an original synthetic occupancy grid and labelled weighted checkpoints. Output is an inspectable route, reviewed mission, execution receipts, inspection issues and a bounded planning-agent dossier.

The broad shortlist rejected another incident retriever, generic workflow bot, packing planner and forecast-only screen because earlier collection projects already cover those workflows. Alternatives here were greedy nearest checkpoint, a chat-only suggested route and exact bounded orienteering. Choose exact bounded planning: grid BFS creates obstacle-respecting metric distances, subset dynamic programming maximizes covered priority subject to travel + inspection + return energy, then reconstructs cell-by-cell paths. Scope is at most 16x16 cells and 10 checkpoints, not physical autonomy. Different problem, algorithm, C++/WASM + JavaScript graph/API architecture and map-first visual language from the inventory project.

## Connected capabilities and release gates

1. Validate/import a versioned map, base, budget, obstacles and weighted checkpoints; persist a single-user workspace with IndexedDB atomic revision checks and portable backup.
2. Run the actual custom C++ route engine in WebAssembly; compare exact reward/cost with independently enumerated small-instance routes, including disconnected targets and asymmetric start/base recovery.
3. Review a route bound to map version, current position, remaining budget and route digest; explicitly start a mission. A model never starts or moves it.
4. Execute movement and inspection checkpoints with duplicate-safe command receipts. Interruption before commit retains the saved revision. Pause, introduce a new exclusion, invalidate the old route, replan from the current position and review before resuming.
5. Record checkpoint inspection PASS/ISSUE evidence, review and resolve issues, then close a returned mission with complete coverage/gap evidence.
6. Run real typed LangChain tools inside a LangGraph decision/observation/human-interrupt graph. Persist/reconstruct saved decisions without model calls, bound investigation steps, reject mutation tools/forged citations and expose actual provider generation/usage/cost receipts.
7. Export workspace and mission dossier; inspect battery conservation, checked/unchecked targets, route cells, exclusions, tool observations, command receipts and measured solver timings.

Invariants: every move is an adjacent unblocked cell; one energy per move or inspection; remaining budget never negative; closed mission is at base; inspected target is current position and not previously inspected; no issue resolves without review note; route is bound to exact map/current mission digest; same command ID/body is idempotent, changed body conflicts; failed command saves no partial state. Browser storage is explicitly single-user, not a hosted shared database. Public APIs operate only on bounded supplied synthetic artifacts; no tenant/auth claim.

Core and integration tests must cover independent route oracles, invalid input, stale review, route reconstruction, obstacle replanning, budget/receipt conservation, interrupted/repeated commands, graph resume/reconstruction, malformed model choices and portable restore. Clean lockfile install/build, actual hosted provider trajectories and desktop/mobile/keyboard workflow checks are required. Benchmarks state runtime/compiler/OS, workload/seed, warmup/repetitions and greedy baseline, not invented scale. Scorecard axes remain pending until release evidence exists. Planned web completion ordinal23, resume-grounded substantive C++/JavaScript/React/Node integrations; no paid infrastructure.

## Design before implementation

Audience: inspection coordinators. Art direction: aerial survey sheet and dispatch console. Pale blue graph paper, near-black navy, vivid safety orange and deep ocean blue; a dominant interactive plan map, thin labelled rails and a bottom mission timeline. No marketing hero or repeated card dashboard. System sans functional text, compact monospace coordinates; 16px body, 12px labels, 28/48px headings, 8px spacing, 3-column desktop workbench collapsing map-first at390px. SVG map has named keyboard-operable cell controls and a text route equivalent. Motion is 160ms opacity/panel translation and immediate current-cell emphasis; reduced motion removes translation. Native dropdowns, modal errors and focus states must stay readable. Actual Motion Primitives component/license reuse is documented; palette exploration, any useful generated asset, screenshots and measured interaction/bundle evidence are recorded honestly.

## Planning/review disposition

User already authorizes autonomous scope choices and publication; no routine approval question is needed. Office-hours premise challenge, engineering/design/eval planning are applied to this contract; outside-model review is unavailable rather than fabricated. Reuse the existing fixed-origin, exact-zero-price provider policy and bounded storage patterns only where their contracts fit, with self-contained source in this folder. LangGraph/LangChain are the user's requested tools for checkpointed reviewed agents; they take precedence over a generic framework default. A process-local checkpointer is only a request execution engine: durability comes from validated persisted decisions and deterministic reconstruction, explicitly tested. No infrastructure badge is claimed from configuration.
